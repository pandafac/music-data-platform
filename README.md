# 音乐数据台 · Music Data Console

> 腾讯音乐高校 AI Hackathon · 赛道一（TME 产品创新功能）
> **把榜单快照，变成一个随时可查的音乐数据台。**

在线体验：**https://pandafac.github.io/music-data-platform/**

---

## 这是什么

音乐平台给用户的是**时刻**——今天的榜单上谁第几。
数据迷要的是**轨迹**——这首歌空降第几、在榜几周、中间有没有掉出去、什么时候回榜、最高到过第几。

这个产品补的就是中间那段：**查得到轨迹，看得懂变化，追得动记录**。

面向三类人：**数据迷**（核心）、歌迷（外围）、内容创作者（生产者）。

## 跑起来

纯静态，**零依赖、零构建**。

```bash
# 方式一：直接双击
demo/index.html

# 方式二：起个本地服务
npx serve demo
```

建议用 Chrome 或 Edge。

### 推荐观看路线

1. **首页** —— 一条会画出来的榜单轨迹 + 一句人话标题；右上角「往年今日」可往回翻历史
2. 往下滑 —— 「找走势」搜歌或歌手；「问数据」用自然语言提问
3. **榜单速览** —— 点任意榜单，看到真实前 30 首（真实名次、封面、涨跌）
4. 点任意一首歌 → **轨迹页**：曲线、逐期名次、关键数字、AI 解读
5. 底部「对比」—— 拖动权重看结论怎么变；「生成对比卡」能直接出图保存
6. 底部「我的」—— 收藏的走势

## 数据说明：真实的说真实，演示的标演示

| 数据 | 性质 |
| --- | --- |
| 榜单名次、在榜期数、涨跌 | ✅ **真实**（平台公开榜单接口） |
| 7 个榜单 · 210 条记录 | ✅ 真实：热歌 / 飙升 / 流行指数 / 新歌 / 欧美 / 韩国 / 日本 |
| 专辑封面 150 张、歌手照片 106 张 | ✅ **真实** |
| 外部热点 | ✅ **真实抓取**（微博热搜 / 抖音热榜 / 百度热搜） |
| 歌曲走势轨迹 | ⚠️ **演示数据**：公开接口不提供历史回溯，轨迹为模拟生成（同一首歌结果确定，末值锚定为真实当前名次） |

**为什么轨迹是模拟的**：公开接口只能拿到"此刻"，拿不到"一路怎么走过来"。
而这恰恰说明——**这件事应该由平台自己做**：平台拥有逐年逐期的榜单归档，正是它独有的数据资产。
产品形态已被本 Demo 验证，平台把历史数据接进来即可上线。

所有模拟内容在界面上都有标注（轨迹卡头部「模拟走势」、指标卡下方说明、AI 解读最后一条）。

## 目录结构

```
demo/            可运行的站点（Netlify 发布目录）
  index.html     入口
  app.js         应用逻辑（路由 / 页面 / 交互）
  data.js        人工整理的样本数据（13 首样本曲、对比维度、热点）
  charts.js      自动生成的榜单数据（7 个榜 · 210 条 · 含歌手照片映射）
  covers-inline.js  封面内联副本（绕开 file:// 下 canvas 跨源限制）
  share-card.js  分享卡生成器（Canvas，无第三方依赖）
  assets.js      矢量图标 / 成就徽章 / 空状态插画
  covers/        本地图片资源（榜单封面 + 歌手照片 + 样本曲封面）

tools/           数据抓取脚本（可重复运行刷新数据）
outputs/         产品文档与界面预览图
```

---

## 刷新数据

```bash
node tools/fetch-charts.mjs    # 榜单 + 专辑封面 + 歌手照片
node tools/fetch-hot.mjs       # 外部热点
node tools/inline-covers.mjs   # 重新内联封面
```

> 这些脚本调用的是**公开可访问的榜单接口**，用于验证产品形态。
> 正式落地应改用 **QQ音乐开放平台（Agent Gateway，需账号绑定的 API Key）**，产品逻辑无需改动。

---

## 三条设计纪律（不可妥协）

1. **数据事实 / 外部热点 / AI 解读三层分离** —— 热点不参与任何计算，解读不冒充事实
2. **演示数据必须标注** —— 不假装有更早的数据、不伪装真实新闻
3. **不做对抗** —— 对比呈现事实，结论由用户自己下；不预测排名、不裁决"谁更红"

## 怎么打开 Demo（30 秒）

进入 `demo` 文件夹，**双击 `index.html`** 即可。无需安装、无需联网、无需服务器。建议用 Chrome 或 Edge。

### 推荐观看路线

- **首页**：顶部是一条会画出来的榜单轨迹 + 一句人话标题；点右上角「往年今日」可以往回翻历史
- 往下滑：「找走势」搜歌或歌手；「问数据」用自然语言提问（试试点那几个建议问法）
- **榜单速览**：点任意榜单，看到真实前 30 首（真实名次、真实封面、真实涨跌）
- 点任意一首歌进**轨迹页**：曲线、逐期名次、关键数字、AI 解读（三种标签：事实 / 热点 / 解读）
- 底部「对比」：拖动权重看结论怎么变；点「生成对比卡」能直接出图保存
- 底部「我的」：收藏的走势（轨迹页右上角可收藏）

## 数据说明（重要）

这个 Demo 对数据的处理原则是：**真实的说真实，演示的标演示**。

| 数据 | 性质 |
| --- | --- |
| 榜单名次、在榜期数、涨跌 | ✅ **真实**，来自平台公开榜单接口 |
| 7 个榜单 | ✅ 真实：热歌 / 飙升 / 流行指数 / 新歌 / 欧美 / 韩国 / 日本，共 210 条记录 |
| 专辑封面、歌手照片 | ✅ **真实**（封面 150 张、歌手照片 106 张） |
| 外部热点 | ✅ **真实抓取**（微博热搜 / 抖音热榜 / 百度热搜） |
| 歌曲走势轨迹 | ⚠️ **演示数据**：公开接口不提供历史回溯，轨迹为模拟生成（同一首歌每次得到同一条曲线，末值锚定为真实当前名次） |

**为什么轨迹是模拟的**：公开接口只能拿到"此刻"，拿不到"一路怎么走过来"。
而这恰恰说明——**这件事应该由平台自己做**：平台拥有逐年逐期的榜单归档，正是它独有的数据资产。
产品形态已经被这个 Demo 验证，平台把历史数据接进来即可上线。

所有模拟内容在界面上都有标注（轨迹卡头部「模拟走势」、指标卡下方说明、AI 解读最后一条）。

## 已知问题（如实记录）

- **发现页还比较薄**：首页目前是"一条头条 + 轮播"，尚未按事件类型（今日空降 / 破纪录 / 最猛异动 / 回榜）分区
- **纪录墙仍是静态条目**：六枚成就徽章已做好，但"纪录由数据算出"的引擎还没接
- **分享卡暂不支持纪录卡**：轨迹卡与对比卡可用，纪录卡的渲染能力已具备、入口未接
- **无浅色模式**：目前只有深色主题

## 技术说明

- 纯静态：原生 JavaScript + CSS + Canvas，**零第三方依赖、零构建步骤**
- 结构：`index.html` + 8 个 JS/CSS 文件 + 本地图片资源
- 图片策略：封面与歌手照片全部下载到本地（共 3.3 MB）；分享卡另存一份内联副本（`covers-inline.js`），用于绕开 `file://` 下 canvas 的跨源限制
- 重新抓取数据：

```
node 数据脚本/fetch-charts.mjs    # 榜单 + 专辑封面 + 歌手照片
node 数据脚本/fetch-hot.mjs       # 外部热点
node 数据脚本/inline-covers.mjs   # 重新内联封面
```
